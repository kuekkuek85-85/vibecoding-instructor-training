# PRD — 영재원 과학교사 바이브코딩 연수 플랫폼

> 2026-08-11(화) 15:30~17:30, 동부중등영재원 협력학교(장평중) 과학 강사 4명 대상 기초 연수 운영 플랫폼.
> 강사(운영자) 1명 + 수강생 4명. 오늘 1회 운영이 목표이며, 이후 산출물 대회 당일 플랫폼의 원형이 됨.

## 0. 개발 워크플로 (오케스트레이션 규칙)

- **기획·설계**: Claude Code가 본 PRD 기반으로 설계 문서/구조 작성 → **Codex MCP 1차 검토** (설계 누락·과잉 지적)
- **구현**: Claude Code 구현 → **Codex MCP 2차 검토** (버그·보안 규칙·엣지케이스)
- **수정 루프**: 수정사항 발생 시마다 Claude Code 구현 → Codex 검토 → 통과 시 **commit + push**
- 커밋 단위: 기능 1개(아래 마일스톤 단위). 커밋 메시지는 `feat|fix: <기능> (codex-reviewed)`
- **시간 제약이 최우선**: 오늘 오후 사용. 마일스톤 M1~M4 순서로 구현하고, 시간 부족 시 M5부터는 컷 가능하도록 의존성 없게 설계할 것.

## 1. 목적 / 비목적

**목적**
- 수강생 4명이 "학생 입장"으로 설계→제작→검토→발표 흐름을 겪게 하는 진행 레일 제공
- AI→자기→동료→교사(강사) **4중 검토**를 설계 단계·산출물 단계 2회 구동
- 강사 대시보드로 4명의 단계 진행/게이트 승인/제출물을 한 화면에서 모니터링
- 플랫폼 자체가 "산출물 수업을 이렇게 운영하면 매끄럽다"는 시연물 역할

**비목적 (하지 않음)**
- 수강생 계정/회원가입 (로그인 없음 — 이름 선택 방식)
- 수강생용 제작 도구 (제작은 외부 캔바 코드에서)
- 범용 LMS 기능, 모바일 최적화 이상의 반응형 완성도

## 2. 사용자와 접속

- **강사 1명**: `/admin` — URL 뒤 쿼리 키(`?key=...`, env로 관리) 정도의 최소 보호
- **수강생 4명**: 루트 `/` 접속 → 이름 카드 4개 중 자기 이름 선택(사전 등록, 물리·화학 위주 구성 가능성 반영해 이름은 seed 데이터로 주입) → 세션은 localStorage에 참가자 id 저장
- 기기: 수강생 노트북(데스크톱 브라우저 기준)

## 3. 핵심 개념 — 단계와 게이트

수강생은 아래 단계를 순서대로 진행. **게이트는 강사 승인 없이는 다음 단계가 열리지 않음.**

| # | 단계 | 내용 | 게이트 |
|---|------|------|--------|
| 1 | 대기 | 슬라이드 동기화 화면만 표시 | 강사가 전체 시작 |
| 2 | 설계 | 연구설계서 7칸 중 '검증 기준' 칸 작성 (나머지 6칸은 과목별 예시로 사전 채움, 수정 가능) | — |
| 3 | 설계 검토 | AI 검토 → 자기 검토(1칸 이상 수정) → 동료 검토(짝 코멘트 1개) → **강사 승인 게이트** | ✅ 강사 승인 |
| 4 | 제작 | 플랫폼이 설계서→캔바 코드용 프롬프트 자동 생성, 복사 버튼. 결과물 링크 제출 | — |
| 5 | 산출물 검토 | AI 검토(결과 vs 가설·문헌 대조) → 자기 검토(한계 1줄 추가) | — |
| 6 | 발표 | 발표회 모드 — 강사가 발표자 지정, 전원 화면에 해당 설계서+링크 표시. 동료 검토(검토관 질문) + 강사 코멘트 기록 | — |
| 7 | 정리 | 오늘 흐름 요약 + "내 수업에 가져갈 것 하나" 입력 | — |

## 4. 연구설계서 데이터 모델 (7칸 + 용도)

```
designDoc {
  usage: "verification" | "explanation"   // 검증용 | 설명용
  question: string      // 탐구질문 → 화면이 답할 질문
  hypothesis: string    // 가설 → 예상 그래프 패턴
  independentVar: string// 조작변인 → 슬라이더
  dependentVar: string  // 종속변인 → 그래프 y축
  controlledVars: string// 통제변인 → 화면 고정값 명시
  verification: string  // 검증 기준 → 실측/문헌 대조 (수강생 직접 작성 칸)
  limitations: string   // 한계 → 무시한 요인
}
// usage=explanation일 때: verification/limitations 대신
//   concept: "설명하려는 개념 1개", accuracyBasis: "과학적 정확성 근거(교과서/문헌)"
```

## 5. Firestore 구조

```
sessions/{sessionId}
  currentSlide: number
  phase: "waiting"|"design"|"design_review"|"build"|"output_review"|"present"|"wrapup"
  presenterId: string|null

sessions/{sessionId}/participants/{participantId}
  name, subject ("물리"|"화학"|"생명"|"지구")
  stage: number (1~7)
  gateApproved: boolean
  designDoc: {...}
  aiReviewDesign: { text, createdAt }
  selfReviewDesign: { changedField, note }
  peerReviewDesign: { fromId, comment }
  canvaLink: string
  aiReviewOutput: { text, createdAt }
  selfReviewOutput: { limitationAdded }
  peerQuestions: [{ fromId, role: "변인"|"검증"|"한계", question }]
  instructorComment: string
  takeaway: string
```

- 실시간 반영: Firestore onSnapshot 구독 (수강생 화면·강사 대시보드 모두)
- 보안 규칙: 오늘 1회 행사용이므로 read/write 허용하되 sessionId를 랜덤 문자열로. (Codex 검토 시 이 트레이드오프 명시 인지할 것)

**① 설계 검토 프롬프트 (요지)**
> 너는 중학 과학 탐구 지도교사다. 아래 연구설계서를 검토하라. (a) 조작·종속·통제변인이 논리적으로 맞물리는지 (b) 검증 기준이 실측/문헌 대조로 가능한지 (c) 탐구질문과 시뮬레이션 화면 구상이 일치하는지. 잘된 점 1개 + 보완점 2개, 각 1문장. 코드 얘기 금지. 존댓말.

**② 산출물 검토 프롬프트 (요지)**
> 아래 연구설계서의 가설과, 수강생이 보고한 시뮬레이션 결과 요약을 대조하라. (a) 결과가 가설·과학 원리와 부합하는지 (b) 문헌값/실측과 대조할 방법 제안 1개 (c) 한계에 추가할 요인 1개. 각 1~2문장. 존댓말.

- 설명용(usage=explanation)일 때는 "개념의 과학적 정확성" 중심 프롬프트로 분기.

## 7. 화면 명세

### 수강생 화면 `/`
- 상단: 현재 단계 스테퍼(1~7), 게이트 잠금 아이콘
- **슬라이드 동기화 영역**: 강사가 넘기는 슬라이드 이미지가 phase=waiting 및 강의 중 표시 (슬라이드는 이미지 URL 배열로 관리, 강사 currentSlide 값 구독)
- 단계별 본문: 위 표의 단계 UI. 설계서는 7칸 폼(6칸 사전 채움 + 검증 기준 강조 표시)
- 제작 단계: "프롬프트 생성" 버튼 → 설계서를 정해진 템플릿으로 조립해 표시 + 복사 버튼 + 캔바 코드 링크 제출 입력
- 발표 모드: presenterId가 자신이면 "발표 중" 배지, 아니면 발표자의 설계서·링크·검토관 질문 입력 폼(자기 역할 표시)

### 강사 대시보드 `/admin`
- **4명 카드 그리드**: 이름/과목/현재 단계/게이트 상태/제출물 링크/AI 검토 결과 미리보기
- 전체 제어: phase 전환 버튼, 슬라이드 이전·다음, 발표자 지정 드롭다운
- 게이트: 각 카드에 [승인] 버튼 (설계 검토 완료 조건 충족 시 활성화)
- 발표 시 코멘트 입력란(카드 내)
- 정리 phase: 4명의 takeaway 한 화면 표시 (마무리 낭독용)

### 캔바 코드 프롬프트 템플릿 (제작 단계 자동 생성)
```
다음 과학 시뮬레이션 위젯을 만들어줘.
- 목적: {question}에 답하는 화면
- 슬라이더: {independentVar} 1개만
- 그래프: x축={independentVar}, y축={dependentVar}
- 화면에 고정값으로 명시: {controlledVars}
- 예상 패턴: {hypothesis}
- 기능은 위 1개만. 로그인/저장/장식 애니메이션 금지. 한국어 UI.
```

## 8. 기술 스택 / 배포

- Next.js(App Router) + Firebase(Firestore) + Vercel 배포
- env: `GEMINI_API_KEY`, `ADMIN_KEY`, Firebase config
- 스타일: Tailwind, 단정한 교육용 톤(다크 배경 강의 화면 고려). 완성도보다 가독성.

## 9. 마일스톤 (시간 컷 라인)

1. **M1** 세션·참가자 seed + 수강생 이름 선택 + 단계 스테퍼 + 강사 phase 제어 (뼈대)
2. **M2** 설계서 폼(사전 채움) + 강사 대시보드 카드 + 게이트 승인
3. **M3** Gemini AI 검토 2종 + 자기/동료 검토 입력
4. **M4** 프롬프트 자동 생성·복사 + 캔바 링크 제출 + 발표 모드(발표자 지정·검토관 질문)
5. **M5** 슬라이드 동기화 (컷 가능 — 강사가 별도 화면공유로 대체 가능)
6. **M6** 정리 phase takeaway + 폴리싱 (컷 가능)

## 10. Seed 데이터 (설계서 예시 풀)

물리·화학 위주 6개 + 생/지 백업 2개. 각 예시는 7칸 중 verification만 빈 값.
- 물리: 진자 길이–주기 / 경사면 각도–가속도 / 용수철 상수–진동수
- 화학: 온도–용해 속도 / 농도–반응 속도 / 촉매 유무–분해 속도
- 생명: 개체군 성장(먹이량–개체수)
- 지구: 단열재 두께–내부 기온 변화

수강생은 이름 선택 후 예시 풀에서 소재 1개를 고르면 designDoc에 복사됨.
